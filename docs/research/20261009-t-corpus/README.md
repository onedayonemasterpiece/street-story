## Дополнительный слепой прогон T-v4 — отдельная проверка, не подмена первоначального корпуса

В исправленном запросе **нет контрольных SID, OSM ID, названий и примеров адресов из набора**. SOURCE и статьи получены независимо из сохранённых оригиналов, Prussia39 и OSM. Для каждого ответа отдельно повторены текущий `freeze_architectural_text_proof`, `verified_publisher_physical_scope` и `source_subject_competition_guard`.

- **14 зарегистрированных T-v4 вызовов:** 11 закрытых ответов, из них 10 соответствуют строгой схеме и 1 не соответствует; ещё 3 исхода провайдера остались неопределёнными после намерения отправки.
- **3 правильных подтверждённых физических ID:** **Photo102, Photo104, Photo132**. Проверка источника, дословных цитат, физического адреса и конкурирующих контуров пройдена. Ни одного ошибочно принятого ID в завершённой проверенной подвыборке.
- Photo108 и 131 дали `uncertain` вместо прежних ложных физических принятий. Photo130 снова предложил соседнее здание, но его доказательство не принято. Для комплекса Photo106 и 110 физический proof также не принят.
- Ещё **8 фотографий с географической опорой не получили повторного вызова v4**; Photo111 не имеет пригодной географической статьи в этом поиске, а 124/127/128 обрабатывались ранее отдельным маршрутом без GPS. Отправки Photo120/121 были заблокированы на стороне инструмента **до создания новой квитанции** — это не результат модели. Предыдущий Photo120 Accepted относится только к первому прогону.
- Время закрытого модельного ответа T-v4: медиана **6,312 с**, диапазон **4,623–10,823 с**. Денежная стоимость провайдером не сообщена; повторные операции исследования нельзя трактовать как стоимость одного production запроса.

## Универсальные исправления T

1. **Prussia39 transport.** Переиспользование адресной/координатной форм, проверка Windows-1251, пагинации, raw SHA. Новый буквальный `title_search` для SOURCE без GPS. HTTP200/empty не означает отсутствующую статью.
2. **Связь статьи с объектом.** Актуальный postal address из статьи получен из отдельной metadata-таблицы HTML. Соответствия «22», «22А», «22/24», «22, 24», «6» и «6А» не смешиваются. Два проверенных отдельных OSM-входа 22+24 могут покрывать полный адрес 22,24 одного контура, но не автоматически доказывают SOURCE.
3. **Семантика.** LLM получает SOURCE, только реальные архитектурные описания и независимо наблюдаемые OSM связи. Различает комбинации эркеров, фасадных осей, проёмов, фронтонов, порталов, крыши, этажности; исторический текст и похожая кирпичная кладка без такой комбинации не становятся identity.
4. **Fail-closed приёмка.** `verified_publisher_physical_scope` требует доказанную полную связь publisher→physical footprint, без автоматического присвоения целого комплекса отдельному корпусу. `source_subject_competition_guard` не позволяет T принять более дальний физический объект на EXIF-координатах без независимого SOURCE→G, когда перед ним имеются другие наблюдаемые контуры. Независимая геометрическая identity G не обязана ждать T.
5. **Никакой новой очереди, БД POI, orchestration или Android.** Блок T подготавливает компактное сравнение в существующий bounded joint2. Уже полученная статья остаётся в `architectural_text_proof.source_text_receipt.articles` для fact review / POI-memory без повторного поиска.
