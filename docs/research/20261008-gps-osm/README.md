# Street Story: воспроизводимое исследование GPS и OSM, 8 октября 2026

Пакет содержит девять сохранённых пространственных снимков OpenStreetMap, минимальные метаданные девяти оригинальных фотографий и код пересчёта. **Фотографий, превью, референсов и полных текстов сторонних статей здесь нет.** Сеть и продуктовые сервисы для воспроизведения не нужны.

В оригинальных файлах 104–112 были получены **девять GPS-координат**. Направление камеры и измеренная горизонтальная погрешность GPS отсутствовали во всех девяти. В ходе геометрического исследования и его офлайн-воспроизведения **provider inference не выполнялся**. Это не утверждение об автоматическом успехе Street Story.

## Запуск

Требуется Python **3.10 или новее**. Вычисление геометрии и таблиц использует только стандартную библиотеку. Установка зависимостей, сетевой доступ и ключи не требуются.

Из этой папки:

```bash
python3 -I -S reproduce.py --output reproduced
```

`-I -S` исключает пользовательский Python-path и site-packages. Wrapper сам загружает только три проверенных локальных helper script. Можно запускать и из другой рабочей папки, передав полный путь к `reproduce.py`: пути входов определяются относительно самого файла, а `--output` — относительно текущей рабочей папки.

Только проверить целостность пакета:

```bash
python3 -I -S reproduce.py --verify-only
```

Перестроить также карты, если matplotlib уже установлен:

```bash
python3 -I reproduce.py --maps --output reproduced-with-maps
```

Для карт нужен matplotlib; для метрик он не импортируется. Шрифты и версии matplotlib могут менять пиксели PNG. Геометрические таблицы сравниваются с ожидаемыми результатами побайтово; совпадение PNG по hash не требуется. Готовые карты уже включены в `research/osm/`.

## Что делает wrapper

1. Проверяет SHA-256 и размер всех входов, перечисленных в `provenance.json`, включая gzip, fetch metadata, нормализованные EXIF-данные, helper scripts и ожидаемые таблицы.
2. Распаковывает XML в новый временный каталог и сверяет SHA-256/размер распакованных bytes с исходными `photo-*.fetch.json`. Несовпадение прерывает работу до расчёта.
3. Выполняет все девять локальных geometry calculations. Каждый вызов использует `local_only=True`. Дополнительно Python audit hook запрещает сетевые операции во всём процессе, включая загруженные helpers.
4. Пересчитывает target matrix, сценарии чувствительности и подробную сводку; проверяет их равенство `expected/`.
5. Сохраняет три компактных результата и `verification.json` в выбранный output. Большие промежуточные `geometry.json` и распакованный XML удаляются вместе с временным каталогом.

Пересчёт не запускает изображение через vision-модель, не ищет внешние фотографии, не вызывает продуктовый backend и не проверяет извлечение фактов. **`offline_reproduction_pass` означает воспроизводимость сохранённой математики, а не product PASS.**

## Структура

```text
README.md
reproduce.py
provenance.json
geo_originals/gps-manifest.json
research/geometry_research.py
research/plot_geometry.py
research/summarize_geometry.py
research/osm/photo-104.osm.gz ... photo-112.osm.gz
research/osm/photo-104.fetch.json ... photo-112.fetch.json
research/osm/photo-104.map.png ... photo-112.map.png
expected/target_geometry_matrix.csv
expected/gps_sensitivity.csv
expected/target_geometry_summary.json
verification/offline-run.json
verification/offline-maps-run.json
```

`geo_originals/gps-manifest.json` — **research expected data**, нормализованное из проверенных EXIF. Сохранены только ID случая, SHA оригинала, GPS, размер, orientation, focal metadata и признаки отсутствующих heading/error. Самих original bytes здесь нет, поэтому пакет не может заново подтвердить EXIF из фотографии: он воспроизводит расчёт из зафиксированных метаданных. SHA оригиналов позволяет владельцу связать эти данные с отдельно сохранёнными файлами.

`photo-*.fetch.json` сохраняют исходные URL, bbox, время получения, размер и SHA XML. Измеренный там `elapsed_s` — время исходного сетевого получения, **не офлайн latency и не продуктовый benchmark**. Gzip создан воспроизводимо, с нулевым gzip timestamp. XML внутри сохранён без преобразований.

При упаковке обнаружена разница точности первоначального CLI: для 104–106 его координаты были округлены до десяти десятичных знаков. Пакет использует полные числовые значения EXIF. Обе CSV остались побайтово прежними; в подробном JSON пересчитаны 108 неокруглённых числовых полей, максимальное отличие составляет около **0,00000248 м**. Это микрометровая численная нормализация, не уточнение реальной точности GPS. Старый и новый SHA подробной сводки и величина изменения записаны в `provenance.json`.

## Ожидаемые цели и ограничения исследования

В `summarize_geometry.py` таблица `TARGETS` содержит вручную установленные исследовательские OSM IDs. Отдельные диагностические ветки для 107 и 110 описывают уже установленную часть здания/историческую связь. Эти annotations нужны, чтобы измерить ранг правильного объекта и проверить гипотезы аудита. Они **не являются поисковым алгоритмом, runtime hints или разрешением подмешать адреса и ответы в обычный upload**. Строка `parent_verified_target` в исходном helper означает вручную подтверждённую исследовательскую цель; это не автоматическая модельная верификация.

Для **111** после независимого ручного сравнения добавлена исследовательская цель **way/95290265**, Дмитрия Донского, 15. Она занимает 21-е место по расстоянию до границы и bbox center; соответствующие расстояния — 188,78 и 215,65 м. Таблицы и карта включают эту цель. Подтверждены общие видимые элементы корпуса; верхний остеклённый фонарь и шпиль не видны целиком в референсах. Отдельный контур круглой башни в OSM не установлен, поэтому расстояние до ближайшей границы здания не выдаётся за расстояние до изображённой башенки. Эти границы доказательства сохранены в подробной сводке.

Не подключайте эту папку к production candidate selection, web query generation или provider prompts. Runtime допускает универсальную математику и извлечение доступных входов; закрытые ожидаемые ответы допустимы только в исследовательской проверке/изолированных regression tests. Смена входного XML, координат, helper policy или target annotations требует новой версии provenance и ожидаемых результатов.

Снимки OSM охватывают прямоугольные окна: восемь с полуразмером 240 м и один 420 м. Это не круговой радиус гарантированного coverage. Полученные полные ways могут выходить за границу bbox, а relation members могут быть неполными. Ранги определены среди полных **полученных групп физических зданий**, не среди всех существующих домов и не среди результатов Nominatim.

Система координат — локальное метрическое приближение с радиусом Земли 6 371 008,8 м для субкилометрового окна. Это не геодезическая съёмка. Расстояния до границы, заполненного полигона, bbox center и центроида имеют разные значения. Ближайшая граница сложного объекта не обязана быть фасадом или башней, показанными на фото.

Сценарии смещения GPS: 49 фиксированных узлов сетки внутри каждого диска 10/30/60 м. Это **не вероятности, не измеренная точность телефона и не доказанные экстремумы по всему непрерывному диску**. HFOV/VFOV — условные оценки из 35-мм эквивалента и orientation; неизвестный crop и калибровка ограничивают интерпретацию. DigitalZoomRatio второй раз на f35 не умножается.

Топология использует node IDs, outer/inner rings, раздельные компоненты и связь частей с родителем; неполнота сохраняется явно. Диагностика направленности граней и самоперекрытия относится к плану в 2D. Высоты, рельеф и точная поза камеры не восстановлены; геометрия сама по себе не доказывает визуальную identity.

## Проверенное время воспроизведения

Проверено копирование пакета в новый путь с пробелами и запуск из посторонней рабочей папки. Финальный запуск с `-I -S`, без site-packages, пересчитал все девять случаев, включая установленную цель 111, и подтвердил три ожидаемых файла за **3,523 с**. Изменение одного байта gzip в отдельной копии было отвергнуто по SHA до распаковки. Обновлённая карта 111 отдельно перестроена за **2,259 с** и совпала с включённым PNG побайтово.

Основной receipt находится в `verification/offline-run.json`. Он фиксирует hashes расчётных входов и ожидаемых outputs, отдельные интервалы проверки hashes, распаковки, расчёта девяти snapshots, summary/сравнения и общее время, а также версию Python. В `verification/offline-maps-run.json` сохранена отдельная проверка перестроения изменённой карты 111 с matplotlib. Остальные восемь карт не менялись; новый полный цикл их рендера не выполнялся. Эти локальные CPU-замеры не обещают latency на другом компьютере и не оценивают работу приложения.
