## Исходные данные и происхождение

Все пять исходных фотографий и пять пользовательских карт просмотрены. [source-context.json](source-context.json) связывает Telegram URLs, SHA оригиналов и ориентированных превью, SHA скриншотов и происхождение координат. В 106 координаты взяты из original EXIF; в остальных четырёх это приблизительные подсказки владельца. Original bytes этих четырёх не содержат GPS. Окружности и смещённые точки на картах являются сценариями; heading и GPS accuracy не были измерены.

Исходные фото, скриншоты с пользовательскими пометками и сторонние reference-фотографии не включены в Git-пакет. Их отсутствие в этом каталоге не означает, что SOURCE не рассматривался. Исследователь знает подсказки владельца и предыдущие результаты; этот проход не является слепым модельным benchmark. Внешние фотографии при новом геометрическом выборе не искались и не использовались как обязательный gate.

OSM 106 повторно использован из [первого пакета](../20261008-gps-osm/). Для 125/126/130/132 выполнены **четыре новых OSM API map-запроса, без повторов**. Каждый XML сохранён как `.osm.gz` со своей `.fetch.json`: URL, bounds, время получения, размер и SHA несжатых bytes. Окна — приблизительно ±200–240 м, в зависимости от кейса; точные bounds находятся в manifests. Использовались реальные OSM primitives, а не восстановленные по скриншотам координаты.

Сборка полного XML-контура и отсутствие unresolved rings не доказывают полную актуальность OSM. Например, у 125 устаревший `historic=ruins` расходится с видимым восстановленным фасадом, а у 126 адрес северного соседа расходится с пользовательским скрином. Геометрический proof не переносит автоматически эту уверенность на отдельные теги или исторические утверждения.

## Как воспроизвести

Пакет располагается рядом с уже включённым `20261008-gps-osm`. Нужны Python 3, matplotlib и Pillow. Исследовательские скрипты по умолчанию не обращаются к сети; они читают сохранённые gzip XML. Выполнять в копии, если требуется сохранить неизменными доставленные PNG/JSON: скрипты создают производные файлы рядом с собой.

```bash
python docs/research/20261008-spatial-proof/kaliningrad/reproduce.py
python docs/research/20261008-spatial-proof/sovetsk/reproduce.py
python docs/research/20261008-spatial-proof/gymnasium/case132.py
```

Калининградский и советский скрипты используют включённые копии существующего geometry helper; 132 использует helper соседнего `20261008-gps-osm`. Оси E/N выражены в метрах в локальной плоскости с R=6371008.8. Углы и расстояния вычислены из сохранённых векторов. Наборы назначений A/B/C, стороны и якоря заданы как явные исследовательские гипотезы для проверки наблюдаемой сцены; это не runtime-правила распознавания по адресам.

Конечные сетки поз — диагностические сценарии с ограничениями, описанными в JSON. Число подходящих поз не является вероятностью. В 106/125 не выполнялся исчерпывающий поиск всех соответствий; сохранён `computed_uniqueness=false`. «Принято» означает достаточное совместное человеческое photo+map решение, а не формальный сертификат решателя всех возможных поз.

## Что переносится в код

[Gate review](spec-review/gate-review.md) показывает реальные места, где рабочий код требовал внешний REF для accepted identity, контекста и повторного использования POI. Срез рабочего дерева был dirty и неатомарный; текущая реализация и deployment не объявляются проверенными. Кодовый агент должен перечитать текущие функции и сохранить параллельные изменения.

Переносить следует общий путь `SOURCE + map → accepted physical identity → subject-bound facts`, единый accepted predicate и право модели остановить identity search без REF. Не переносить в runtime выбранные здесь OSM IDs, правильные ответы или подсветку диагностических карт. На слепой проверке источник, нейтральные геометрические данные и допустимые подсказки должны иметь явное происхождение.

Цель около 30 секунд относится к обработке при уже доступном SOURCE; полное время от приёма/загрузки фото и время первого eligible fact фиксируются отдельно. Измеренные времена OSM fetch и локального рендера — результаты исследовательских инструментов, не latency продукта. Новых продуктовых inference, canary, deployment и внешних фотопоисков в этом проходе **ноль**.
