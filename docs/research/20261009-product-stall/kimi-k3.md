## Проверка заключения основным аудитором

Полезное: Kimi ставит адресную область каталога перед очередным общим reask; поддерживает явные address/membership joins, отсутствие нового judge, один cold102 и разделение quota/recognition. Он сохраняет требование трёх фактов после первого полезного результата.

В окончательную постановку **не перенесены** следующие положения:

1. **«Мир из одной карточки» не равен набору физических кандидатов.** Prussia catalogue имел одну карточку, но SOURCE/MAP input содержал716 OSM ID, включая правильный footprint113 и его входы. Alternatives не были пустыми во входных данных — их не рассмотрела модель. Поэтому нельзя назвать исключение правильного физического кандидата из входа доказанной единственной причиной. Исправлять нужно представление/использование имеющегося контекста и предметный lookup, а не просто увеличивать pool.
2. **SID3875 не является OSM object и не был в runtime-кэше299 по установленным данным.** Он известен из отдельного исследовательского cache и другого canary. В текущем пакете были way113 и его адреса, достаточные для обычного поиска статьи; жёсткая недостижимость3875 не доказана.
3. **Focal/orientation/zoom не задают физический радиус100–300м сами по себе.** Для дальности нужны обоснованные размер/видимая часть объекта, перспектива и неопределённость. Фиксированный буфер сломает допустимые дальние/теле-сцены и снова создаст cutoff.
4. **Нет требования catalogue≥2 или обязательной3875.** Статья — не physical candidate; уникальная geometry может закончить identity вообще без каталога, а одной достаточно различающей статьи может хватить text-пути. Expected SID допустим в отчёте/fixture, не в runtime prompt.
5. **Catalogue bias остаётся причинной гипотезой.** Ответ Kimi сначала называет его доказанным root cause, но в конце сам требует подтверждающий запуск. Исходные данные доказывают асимметрию входа и неправильный ответ; контролируемой изоляции причины не было. Фраза о том, что92k chars/716IDs «читаемы», не является результатом проверки модельного восприятия. Oversize text fallback — отдельный реальный функциональный дефект.

Фраза `stop→first atomic fact` в ответе не принята буквально. Правильная последовательность: wrong identity→обычный Stop; correct identity→продолжить до первого reviewed fact и полного порога.

## Findings (ранжировано)

1. **Root cause — biased catalogue, а не модель.** Подтверждено: initial packet содержит ровно 1 карточку (2306/Коперника21), хотя в том же пакете уже есть nodes 1876020727/1876020730 (Житомирская 22/24, члены way 133035113). Потеря результата — в сборке catalogue, до любых reasoning guards.
2. **Geometry-proof путь формально сработал, но против пустого множества кандидатов.** Freeze проверяет hashes/refs, не геометрическую истину; alternatives=[] допустимо → re-ask на missing alternatives здесь бесполезен: предлагать нечего.
3. **«Правильное описание Prussia39 существует, но недостижимо».** 3875 есть в полном OSM-пуле и в кэше с точным описанием эркера; он отфильтрован скоупом по улице камеры. Это доказанный факт по данным, а не blind spot распознавания.
4. **Квота — отдельный блокер, не причина неверного ответа.** 299 не отправлял ни одного SDK-вызова 3.8 (6 ключей not_sent, shared RPD), 1 Lite-ответ ≈67k reported tokens. Способность 3.8 **не измерена** — вывод «модель слабая» из Lite-фейла не следует (согласен с оговоркой в вопросе).
5. **Раздувание промпта вторично:** 92k chars / 716 MAP IDs читаемы, но могильный риск — Live 24KB reject при text-fallback (size проверяется до schema append; контракт движения компактный). Это latency/cost-issue, не identity-fixer.
