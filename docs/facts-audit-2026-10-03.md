## Последнее уточнение к зафиксированному снимку

Основной аудит описывает снимки A→B→C, до `4b87cd84d062f2fb0e83ee6e12d62d5872738067`. Во время подготовки документов в продуктовую ветку был добавлен D=`2cff062cb8d17f68afc8f5e57f413701dda8fb96`, родитель C, commit «Make grounded fact normalization fail soft (#105)» от 05:47:36 UTC.

Перед сдачей прочитан [diff PR #105](https://github.com/onedayonemasterpiece/street-story/pull/105/files); он меняет `providers.py` и соответствующий тест. Это уточнение имеет приоритет над описанием старого состояния F10 в основном документе и вводной части промпта.

### Что уже исправлено в D

Основной Google-grounded `search_web` тоже перешёл на нормализацию отдельных facts вместо прежней строгой проверки каждого элемента, срывавшей весь payload. Добавлены fallback для пустого/слишком длинного claim_key, default confidence при неверном числе, extraction_audit с причинами исключений и проверка URL по реально найденным grounding sources. Prompt теперь просит до 32 фактов и явное разделение списков людей/дат/ролей.

Следовательно, **не нужно заново выполнять исправление «основной маршрут всё ещё требует 20 фактов и падает целиком из-за неверной confidence одного факта»**. Это описание верно для C, но устарело для D. Изучение diff не равно новому запуску теста или проверке телефонной сессии; deploy D этим аудитом не подтверждался.

### Что этим изменением не решено

Срез первых 32 элементов остаётся, continuation для остатка не добавлен. Полный жизненный цикл кандидата, repair/quarantine и сквозная сверка всех исключений остаются частью F10. Срез сериализованного topic context, неполное чтение страниц, отсутствие manifest обработки всех chunks, pass-2 replacement, merge несовместимых значений по одному ключу, перезапись supports одного URL и необходимость версионного арбитража сохраняют актуальность: соответствующие участки этот patch не меняет.

Нельзя путать новый тест нормализации с измерением recall: mock возвращает заранее заданное имя и grounding metadata. Он полезен для проверки fail-soft границы, но не доказывает, что модель нашла три фигуры по широкому запросу, прочитала страницу и корректно связала доказательства.

## Зафиксированное решение

Мира ведёт диалог и руководит исследованием. Существующий настроенный текстовый LLM может выполнять пакетное извлечение/сравнение за явным контрактом; смысл не переносится в regex. Исследование становится отдельной сохраняемой операцией в существующем backend с версиями документов, полным учётом принятого текста и адресными доказательствами.

Исходные observations и конфликтующие варианты не перезаписываются. Эквивалентность и арбитраж — модельные решения, привязанные к версиям. Выбор автора отделён от допуска к использованию. Недоступная проверяющая модель означает unreviewed/partial, не «конфликтов нет». Для первого надёжного UX рекомендуется явная пауза микрофона на время исследования с отменой, восстановлением и защитой от старого PCM; она не заменяет устойчивость backend.

## Что действительно проверено

Прочитаны источники кода, официальная документация Live и ограничения модели; проведён read-only review через OpenCode с независимой проверкой выводов. Локально выполнено шесть probes чистых функций: четыре контрпримера и два контроля поведения. Полный `model_facts.py` A проверен по git blob SHA-1 перед запуском. Новые Live/provider calls, телефонная E2E-проверка, изменения production-БД и публикации не выполнялись.

Контрольный acceptance на следующий этап — широкий и направленный запросы о Королевских воротах с вручную проверенным корпусом, тремя отдельными фактами о фигурах, точным evidence и без передачи ожидаемых имён в input широкого теста. Добавить holdout объекты. Счётчик facts не заменяет precision/recall, качество атрибуции, проверку конфликтов и сохранность после reconnect.

Порядок чтения: это уточнение → полный аудит/to-be → промпт. Новые изменения после D следующий исполнитель проверяет коротким diff, а не начинает исследование проекта заново.
