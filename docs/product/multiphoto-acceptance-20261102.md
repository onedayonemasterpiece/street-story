## Минимальные сценарии, которые обязаны закончиться фактическим PASS

- [ ] **Старая вилла** на *реальном обновлённом телефоне*: версия APK прочитана из приложения; «Готово» → уйти → вернуться → два выбранных и только они → «Изменить выбор» → все кандидаты с сохранёнными галочками → снова «Готово»; порядок и обложка сохранились.
- [ ] На этой же вилле подпись `рантава.рф` без «Xn...»; переход открывает исходный URL.
- [ ] **Новая история** из реестра ПМИ с GPS: выбор двух несоседних фото и карточек, полное создание текста и планов; не останавливать на одном скриншоте.
- [ ] Название POI на **обложке** видно крупно вместе с зачином; для виллы — «Вилла Зее-Адлер» по умолчанию; проверить смену названия через концепцию/редактуру без автоматического возврата старого названия.
- [ ] По **двум фото** получено **три** изображения: два сюжетных с исходными ракурсами + третье независимое, текстоцентричное, «История за поворотом» с городом и адресом. Карточки можно перелистать и посмотреть до команды публикации.
- [ ] Подтверждены факты и связанная история РКБ без выдуманных ссылок, затем отдельно — публикация альбомом только по явной команде владельца.

## Действия и границы

**Сейчас:** Android PR 324 — минимальный legacy и IDN fix (+6 net production), существующий один регрессионный Android-тест + существующий unit-тест, сначала RED, затем GREEN, независимое критическое ревью до merge/release. На телефоне не проверено — инцидент открыт.

**Следующий независимый backend пункт:** N фото + отдельная финальная и редактируемое название обложки с доказанным readback: назначить существующему исполнителю **«Backend-мультифото»** после доступного слота; один различающий live-тест. **Поиск** остаётся у своего текущего исполнителя, **индекс** исключён владельцем.

Каждый PASS в этом документе требует ссылки на реальную проверку и дату; предыдущие эмуляторные PASS рядом с живым FAIL не закрывают пункт.
